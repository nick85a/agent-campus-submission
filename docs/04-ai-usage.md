# 04 AI 使用与我的贡献

## 我如何使用 AI

我在这个项目中使用 Codex 辅助完成需求拆解、方案设计、代码生成、测试设计、问题定位和文档整理。项目的主要代码、合成数据、自动化测试和运行脚本由 AI 辅助生成和修改。

我借助 AI 搭建了 Pi SDK、TypeScript 和 SQLite 的实现，并围绕素材读取、规则检查、时段查询、本人确认、草稿保存和失败恢复完善业务闭环。我要求模型选择动作，由业务服务核验状态、授权和真实保存结果。

我要求通过 Pi 扩展的 `pi.on` 订阅工具生命周期，让工具实现与 Trace 采集分离，并要求聊天接口只返回业务结果，将运行记录保留在后台。

我通过 AI 辅助排查默认渠道引用、模糊确认、补资料以及终端重启恢复的问题。相关代码修正与回归测试使用了 AI 辅助，验证结果以实际输出和存储记录为准。

## 我作出的业务决策

- 我选择素材审核与发布排期题目，并将交付范围限定为草稿保存和查询。
- 我确定固定发布时间不能由模型擅自改变，时间变更和风险接受需要分别取得本人同意。
- 我要求授权未知时等待补充资料，禁止性风险不能通过确认豁免。
- 我选择通过 CLI 和 HTTP 业务聊天验证流程，要求模型上下文和业务任务都能恢复。
- 我要求重复提交返回同一份草稿，保存失败明确反馈，并检查数据库实际结果。

## 我参与的手工验证

我在终端逐条输入排期、同意、拒绝、素材查询和资料补充等请求，反馈了“统一”后确认丢失、补标题被拒绝，以及重启后无法继续 M06 的问题。代码修复由 AI 辅助完成。

我亲自执行了 `npm run examples -- --mode live`，生成了11组真实 Kimi 场景记录。我随后请 AI 交叉核对输出、16份 Trace、78次工具调用与11个实际 SQLite 数据库；本次11个场景均符合预期，核对结果见 [报告](../examples/live/acceptance-review.json)。

我将自动化测试结果保存在 [验证报告](../examples/checks/verification.json)。报告记录91项测试通过，涵盖确认边界、事务回滚、幂等、并发、执行上限、模型协议和聊天恢复。自动化测试设计、执行和结果核对也使用了 AI 辅助。

我使用的素材、规则和已有排期都是合成数据。脚本中的资料补充、授权、同意和拒绝是测试程序输入，不是真人审批。离线 Mock 只验证流程，真实模型结果以 live 运行记录为准。
