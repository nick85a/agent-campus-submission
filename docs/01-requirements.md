# 01 需求

## 用户与目标

内容运营希望找出尚未处理的素材，获得逐项审核结论、风险原因、无已知冲突的建议时段、待确认事项及可核实的草稿保存结果。硬性发布时间未经本人同意不得改动。

## 核心范围

- 台账读取、待处理清单、指定补充资料源查询和用户资料补充。
- 必填信息、授权状态、合成禁止词与需人工确认警告的规则检查。
- 固定时间或允许窗口内的时段查询，与已有排期、已存草稿、本批建议避让。
- 本人按具体建议和版本确认；确认后复检；事务保存、去重、失败恢复和查询。
- Pi 模型工具循环、执行预算、真实记录与离线入口。
- CLI 与模型工具共用业务命令入口；显式状态机控制合法迁移，并可查询业务项状态历史。

草稿管理限保存与查询；已经保存的草稿出现变化时阻断并交由人工处理。人工环节采用本人确认。运行方式为 CLI。

CLI chat 与 HTTP POST /api/chat 共用业务聊天。真实模式由模型理解自然语言，宿主核对原文依据并控制确认，审核排期复用 Pi 工具循环。业务响应只包含业务结果；观测后台记录。HTTP 会话支持持久化、消息去重与具体确认卡片。

## 业务约定

| 对象 | 约定 |
|---|---|
| 素材 | 必须有标题、内容文本、明确授权状态；`unknown` 或无效授权值不视为通过 |
| 规则 | `passed`、`needs_information`、`needs_confirmation`、`blocked`；返回规则 ID 和证据 |
| 时间 | Asia/Shanghai；有效 ISO 整点；同渠道每个时段容量 1；窗口最多七天、端点包含 |
| 固定时间冲突 | 同日规则时段内提出替代；优先随后由近到远的时段，再考虑前移；必须 time_change 同意才能保存替代时间 |
| 风险 | warning 需 risk_ack；禁止性风险不能确认豁免 |
| 确认 | 原始要求保持不变；同意记录绑定素材版本、规则哈希、建议版本、时段与范围 |
| 批次 | 按输入顺序；此前待确认建议供后续项避让，跨会话不形成持久占用 |
| 重复 | 同 owner/requestId 唯一，输入变更报错；草稿按会话/素材/渠道唯一，时段按渠道/时间唯一 |
| 失败 | 事务回滚，不遗留新草稿或占用；每项每轮最多两次保存尝试 |
| 状态 | checking、needs_information、needs_confirmation、ready、saving、saved、save_failed、blocked、canceled；审核、确认和保存结果分别表达 |
| 来源权限 | 模型可提出建议；本人确认和自由补充资料只能来自可信 CLI；保存时统一复检，不接受模型自报的成功或同意 |

“待确认”是正常业务暂停，不代表已保存。用户拒绝后该建议终止。变更要求可使用新的请求标识重新发起；本期不修改原始要求或已有草稿。

## 成功标准

六项必验：正常排期、资料不足、规则风险、时段冲突、重复提交、保存失败。每项必须输出清楚，且与数据库状态一致。至少实现模型选动作、工具执行、结果回传、模型调整或结束的循环；真实模型证据与离线流程证据分别标注。
